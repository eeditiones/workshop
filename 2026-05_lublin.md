## Po co nam edycje cyfrowe?

- Edycje cyfrowe są kosztowne w produkcji i utrzymaniu
- Mają tendencje do przepadania bez wieści
- Osoby odpowiedzialne za tworzenie edycji zazwyczaj nie mogą liczyć na adekwatne systemowe wsparcie
- Mało się liczą przy ewaluacji

## Czy da się "wyklikać" porządną edycję (i co to znaczy)?

1. Stwórzmy nową edycję w oparciu o blueprint *workbench*
  - w pierwszej zakładce wystarczy wypełnić pole *Abbreviation* (bez spacji, nawiasów, znaków diakrytycznyc)
  - w drugiej proszę zaznaczyć *Workbench* w sekcji *Profiles*
  - i ostatecznie kliknąć *Apply* na dolnym pasku narzędziowym
2. Przegląd podstawowych opcji edycji 
  - przeglądanie kolekcji
  - wyszukiwanie pełnotekstowe, dokładne i z użyciem wzorców `?` i `*`
  - filtrowanie fasetowe
  - API
  - panel administracyjny
3. Rzut oka za kulisy
  - eXide
  - zakładka Files
3. Importowanie własnych dokumentów
  - w TEI XML
  - konwersja z DOCX
4. Przykładowy workflow
  - Pobrać [plik](https://docs.google.com/document/d/15xV3VRhn62impuNHqSa7Uw4CUUyp7dFgKVuWwhspY1I/edit?usp=sharing) w formacie DOCX (Microsoft Word)
  - Zaimportować do bazy danych przez kontrolkę *Upload/Prześlij*
  - Dodać brakującą sekcję `teiHeader` via *eXide*
  - Użyć *edytora anotacji* do oznakowania osób i terminów oraz powiązania ich z lokalnymi lub zewnętrznymi kartotekami wzorcowymi

```xml
<teiHeader>
      <fileDesc>
         <titleStmt>
            <title>Rok ogrodnika. Żywot świętego Georgina z Dahlii.</title>
            <author>Karel Čapek</author>
         </titleStmt>
         <publicationStmt>
            <p>Publication Information</p>
         </publicationStmt>
         <sourceDesc>
            <p>Information about the source</p>
         </sourceDesc>
      </fileDesc>
</teiHeader>
```

## Jinks: po co to komu i czym to się je

Osoby odpowiedzialne za tworzenie edycji mają przygotowanie edytorskie, ale zazwyczaj nie mają adekwatnego wsparcia w tworzeniu edycji cyfrowych; zwłaszcza opartych na standardach i dobrych praktykach. TEI Publisher miał być odpowiedzią na ten problem.

Tym niemniej:

- aplikacje oparte na TEI Publisherze wymagają upgrade'ów
- użytkownicy mogą zechcieć zmienić konfigurację w dowolnym momencie
- jeden wzorzec aplikacji jest niewystarczający: wiele typów edycji dzieli rozwiązania funkcjonalne, ale w praktyce nie mamy już wyraźnie rozgraniczonych typów edycji
- rozwiązania zaimplementowane w jednej aplikacji czasem niełatwo jest przenieść do innej, poniewa wymaga to precyzyjnej orkiestracji poszczególnych warstw i elementów systemu: od organizacji i znakowania danych, po moduły programistyczne, szablony stron czy ODD

```json
      "palette": "green"
    }
  },
```

```json

    "search": false,
    "login": false
  },
```

## Part 3: It all starts with the data

### Dataset 1

- Install the [Laks data package](data/xars/laks-data-1.0.xar) into eXist (via package manager)
- Using the same Jinks config as before, change the data and data default to use the external data package

```json
  "defaults": {
    "data": "/db/apps/laks-data/data",
    "data-default": "letters"    
  },
```
- See how documents are accessed by their file name, e.g. `letters/laks-correspondence-335.xml`

- Change the addressing method to use `xml:id` attributes

```json
  "defaults": {
    "data": "/db/apps/laks-data/data",
    "data-default": "letters",
    "address-by-id": true   
  },
```

It still shows some parameters after the id: `SL-335?view=div&odd=teipublisher`. We can control that with `urls` section

```json
  "urls": {
    "ignore": "view, odd"
  },
```

- Analyze the the TEI encoding for letter nr. 8, particularly regarding facsimile connection
- Select the **IIIF feature** and regenerate the application

By itself it doesn't change anything, we need to configure the feature

```json
"features": {
    "iiif": {
      "viewer": "pb-tify",
      "enabled": true
    }
  },
```

- Check the results on the document page

### Dataset 2

- Install [Karl Barth data package](data/xars/kb-data.xar) into eXist (via package manager)
- Remove IIIF feature as this dataset has no facsimiles
- Add registers feature and timeline
- Decide if we want registers in the document view or not (configure the template front matter?)
- Add edition introduction XML to articles (we can switch momentarily the data default so it lands in the correct spot)
- Add menu option linking to the introduction
